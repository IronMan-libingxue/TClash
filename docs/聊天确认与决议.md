# TClash 聊天确认与决议

## A 端用量、查价和通知

- 原始 Token 与请求保留。设备开关及总览卡片右键菜单共享同一个显示口径。开启后该设备的卡片和单设备明细使用其 B 端设定倍率，跨设备汇总使用真实数据。
- 明细行展开该请求的思考深度。从请求进入会话后，顶部统计该会话在当前周期内所有模型，分思考深度、标准、Fast 和可识别的 Ultrafast。点设备或项目时汇总对应范围内所有有用量的模型。预算占比沿用参考美元除以 A 端设定的预算。
- 价表可以在 Magpie 的 Models.dev 来源和 Agent Speed 之间切换，每日自动更新可单独控制。两张表分别提供可查的基础单价。A 端历史和新同步 B 端记录按选定价表重新估算，价格变动只影响参考金额和预算占比。
- Windows 2 曾出现标准价与倍率价差异，讨论后确认基础单价与档位口径按官方可核对规则处理。截图中的套餐额度提示针对 GPT‑6.1 Sol 和 GPT‑6 Astra，保留用户指定的 2.5 倍与 8 倍文案。精确费用按模型、Token 类型和可验证的档位信息计算。单价缺失时保留未计价状态。历史实测的不同金额仍见原纪要。
- 用量增加触发设备状态通知，持续使用不重复。离开超过十分钟才重新提醒。Fast 使用单闪电，Ultrafast 使用两个闪电与最终确认的品红色。Ultrafast 加多任务并行时用柔和闪烁的红色卡片，每次进入组合状态提示一次。并行项目无法确认时显示「未确认」及会话数。

## B 端、配对与发布

- 早期 TClash Preview 保留 Clash Verge Rev 2.5.10 的代理技术栈。Windows 1 首包和路径修正版均实际报错，读取快捷方式明确了 D 盘实际位置。D 盘修复包完成实机安装和同步。Windows 2 及 Mac 2、3、4 后续采用设备专用安装器。Mac 标准安装目标为「应用程序」。
- B 端随后迁移到 FlClash，程序名为 TClash。仪表盘在服务状态和连接统计之间加入本机用量卡片，CodeX Speed 使用同一应用的界面规范。两处都显示所有模型汇总的参考美元和预算占比，继续提供缓存筛选与同步状态。
- 已安装 B 端原位升级，使用同系统账号。通用包按平台及架构复用，沿用设备原配对、有效令牌和历史。未配对设备仍通过 A 端建立授权。Windows 交付为双击即可安装的 x64 EXE。Mac 的 Apple 芯片和 Intel 分别提供 PKG。
- A 端用当前价表、预算及设备显示倍率发布经过验证的策略。新 B 端在自动同步时获取、验证并更新价表，继续上报原始用量与可识别的 Ultrafast 状态。旧 B 端按原协议继续上传。
- 2.5.12 最终界面强调底部 Fast 说明，把本机预算占比移至卡片右侧，并用蓝色填充表示用量进度。「本机预览」仅显示「本地价格表」或「价格表已更新」。
- 2.5.11 留有用户确认的 Windows 和 Mac 使用记录。2.5.12 留有隔离环境的安装、自动启动和采集验证记录。实体设备与正式 A 端的 2.5.12 联机测试边界详见交接纪要。
