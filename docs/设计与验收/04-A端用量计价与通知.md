## 二、设计指标

### 2.1 B 端显示倍率与设备菜单

- 把「本周期展示参数」标题改为「B 端显示倍率」。每台已配对 B 设备的倍率输入旁增加 A 端显示开关。关闭显示真实用量，打开使用该设备在对应周期的 B 端倍率。单设备系数留空时沿用已有默认倍率。首次升级默认显示真实用量，之后按设备身份记住选择，改名和重启后继续沿用。
- A 端总览设备卡片的右键菜单加入「以真实倍率显示」和「以设定倍率显示」。两项只能勾选一项，和设置页的开关即时联动。菜单、卡片和单设备明细均应能辨认当前口径，开启时标明倍率。
- 倍率覆盖该设备卡片、模型和 Fast 用量分项、单设备明细顶部、会话汇总及逐条请求的 Token 与参考美元。自定义预算占比使用显示后的金额重新计算。请求数、运行会话数、模型速度、代理流量字节均保留原始单位与数值。
- Mac 1、总览顶部跨设备汇总、全部设备的混合视图继续使用真实用量。官方额度取当前所选账号的官方读数。Windows 2 等设备按倍率展示时，使用同一设备、周期、缓存选项与已同步记录对照 B 端 Token。A 端参考金额按第 2.6 节的新口径验收。

### 2.2 单条请求与会话统计

- 点击请求行即在该条附近展开思考深度和模式，保留列表筛选、滚动位置和现有模型筛选入口。深度缺失显示「未记录」，模式缺失显示「档位未知」。日志只证明用户选择时标记「所选」，有可靠实际处理档位时可注明。
- 选中会话后，顶部汇总该会话**当前 Codex 重置周期内所有模型**，覆盖所有分页，并沿用当前设备和账号归属口径。下方请求列表仍可按模型、项目筛选。顶部标出统计范围，缺少可确认的当前周期时明确提示。
- 按「思考深度 × 档位」统计 Token、真实请求数、参考金额及自定义预算占比。`X High · 标准` 与 `X High · ⚡ Fast` 同时出现时分行，仅有 Fast 时显示带闪电的那行。可确认的 `⚡⚡ Ultrafast` 用品红色提示并独立分行，未知记录单列。思考深度中的 `Ultra` 仍按深度记录，Ultrafast 由服务档位记录确认。保留可确认的子代理 Fast 用量归属规则，每条请求计入一次。
- 统计金额按每条请求对应模型和可确认档位计算，再求和。「含缓存 Token」只切换显示的 Token 合计，参考金额按输入、输出及实际记录的缓存用量计算。占比以 A 端该周期设定的**总参考额度（美元）**为分母，例如 `$27.34 ÷ $900 ≈ 3.04%`。有未计价请求时标出数量，已计价部分显示为部分估算。

### 2.3 卡片高亮与 Mac 3 排查

| 可确认的设备当前状态 | A 端卡片 |
| --- | --- |
| 普通用量变化 | 柔和绿色二级高亮，沿用已有普通活跃与未读提示 |
| 有活跃 Fast，未确认同时有多个独立会话 | 柔和蓝色一级高亮，显示 `⚡ Fast` |
| 至少两个独立会话并行，未确认有活跃加速档位 | 柔和黄色一级高亮，显示会话数 |
| 有活跃 Fast，且至少两个独立会话并行 | 柔和红色特级高亮，显示 Fast 与并发 |
| 有活跃 Ultrafast，未确认同时有多个独立会话 | 用品红色边框、低强度背景渐变和 `⚡⚡ Ultrafast` 状态文字提示 |
| 有活跃 Ultrafast，且至少两个独立会话并行 | 用品红色双闪电文字提示档位，以红色缓慢闪烁的边框提示并发，并触发消息弹窗 |

并发只计正在执行任务或等待工具的独立会话。打开但空闲的会话和自动子代理不另计。以同一设备同一次有效观察为依据，Ultrafast 并发优先于 Fast 并发。状态结束或过期后停止闪烁，按最新可信状态回退。闪烁拟用慢速低对比度的边框变化，开启系统「减少动态效果」时用静态红色和文字。 [Apple 动效设计指南](https://developer.apple.com/design/human-interface-guidelines/motion)

Mac 3 的排查以能否复现为准。对照请求的所选档位、会话是否仍在运行、B 观察与上传时间、A 接收时间和实际选中的状态。历史 Fast 在明细保留标记，蓝色高亮以仍在运行的可确认 Fast 会话为准。对上传缺失、过期或 A 端误判分别留存证据。

### 2.4 macOS 设备通知

- 普通使用按**每台 B 设备**收到的真实新增用量触发。第一次开始使用通知一次，持续运行、停止以及停用 10 分钟以内重新使用均静默。可确认停用**超过 10 分钟**后有新用量时再次通知。首次登记或升级时用已有记录建立基准。离线补传的旧请求、重复同步、切换筛选、改倍率或刷新价格不触发通知。
- 确认进入 Fast 或 Ultrafast 时通知设备名、档位图标和可确认的模型。确认进入高并发时通知设备名、独立会话数及可确认的项目，无法确认时写「项目未确认」。模型无法确认时写「模型未确认」。
- 同一同步轮次只发一条该设备最高等级的通知。普通使用、Fast、并发同时进入时发红色等级的「Fast＋高并发」。有 Ultrafast 并发时发优先的「Ultrafast＋高并发」。状态持续期间保持去重，只有从确认结束的状态再次进入时才发相应通知。
- 本稿将「持续闪烁、消息弹窗」落实为**组合状态期间卡片持续闪烁，进入该状态时弹一次**。卡片用绿、蓝、黄、品红、红区分，系统通知用标题、文字和图标区分，Ultrafast 标题带双闪电。macOS 决定横幅样式、显示时长和通知中心呈现。 [Apple 通知内容](https://developer.apple.com/documentation/UserNotifications/UNMutableNotificationContent) · [macOS 通知设置](https://support.apple.com/zh-cn/guide/mac-help/mh40583/mac)

### 2.5 A 端模型与计价更新

- A 端本机复用 Magpie 的请求采集、模型匹配与金额算法，接入它使用的 Models.dev 公共目录，自动读取模型、基础单价和长上下文价格。用量仍取本机可核实的 Codex 请求记录。目录刷新结果提供来源和最近成功时间，方案附计价和使用说明入口。
- 以 OpenAI 对应模型的公开价格补充目录尚未提供的 Fast、Ultrafast 规则，按模型、档位、计价单位及请求时间选择适用项。GPT‑6.2 Sol、Astra 以及 Sol Fast、Ultrafast 为本轮必须覆盖的验证样本。可确认所选档位时可给出「按所选档位估算」。证据不足时保留原始 Token 和请求数，对应档位价格显示未确认。 [OpenAI API 价格](https://developers.openai.com/api/docs/pricing)
- B 端继续采集并上传本机模型用量，并按现有同步流程读取展示参数。已发布 A 端以 B 上报金额呈现远端明细，这一展示口径将在第 2.6 节的改造中更新。

### 2.6 A 端统一计算已同步设备的参考金额

- 「同步设置 → 价格表」的来源选择适用于 A 端显示的本机与所有已配对 B 设备。已同步的历史请求和后续收到的新请求，均用所选的 Magpie 或 Agent Speed 逐条估算。现有 B 上报金额保留在原始记录中供核对。
- 总览、设备卡片、单设备明细、按项目／模型／会话汇总、逐条请求和自定义预算占比使用同一批估算。先按原始 Token 计价，单设备开启设定倍率时再按现有规则折算显示。跨设备汇总用未经显示倍率折算的参考金额。
- 成功切换来源或取得有效的新价表时，更新 A 端已保留记录的参考金额及预算占比。计价说明显示当前来源。无可用费率或缺少该来源所需信息的请求显示「未计价」，仍保留 Token 和请求数。汇总只加总可计价部分，并提示未计价条数。

## 三、技术路线

### 3.1 A 端视图与同步兼容

在 A 端按设备 ID 保存查看偏好，设置开关、卡片菜单和单设备明细读取同一个值。先按原条件聚合，再使用显示倍率。逐条和分组保留计算精度，显示时完成格式化。通知以原始记录标识和真实用量判断，跨设备汇总读取未乘显示倍率的结果。会话顶部汇总独立于模型筛选与分页，逐条展开绑定请求 ID。

兼容层继续验签和解密现有设备数据。已部署 B 的身份、同步间隔、计价字段和策略结构保持兼容。A 端的新开关、目录缓存、档位价格规则和通知记录保存在 A 本地。将来若要让 B 跟随价格更新，需要单独为 B 增加版本识别、目录读取和重新计价能力。沿用当前仓库同步时，延迟受 A 发布、B 下一轮读取及网络影响，目标为下一轮有效同步后生效。秒级更新需要另行设计传输方式。 [现有签名策略读写](../../source/preview/codex-collector/internal/usagetracker/sync.go)

### 3.2 Magpie 计价与目录刷新

1. 复用 Magpie 的目录加载、自动刷新、模型匹配和 `CostSplit` 计价。A 端启动时检查目录是否需要更新，运行中按 Magpie 的周期刷新机制检查。在价格缺失时按现有机制限频尝试。验证新数据后整体切换，网络失败或数据格式无效时使用上次有效目录，首次离线时使用随附目录。查询只访问公开模型目录，A/B 私有同步走原渠道。 [Magpie 目录刷新源码](https://github.com/yetone/magpie/blob/main/internal/catalog/fresh.go) · [Magpie 用量计价说明](https://github.com/yetone/magpie/blob/main/docs/reference.md)
2. 本机逐请求计价保留完整长上下文分档。按型号定位目录价格，用含缓存的输入长度匹配上下文档，按未命中输入、缓存读取、输出及确有记录的缓存写入分项计价。金额汇总以逐请求结果为准。GPT‑6.2 的独立速度规则如未出现在目录中，使用有官方来源和生效日期的随 A 版本发布的规则。目录价格可自动更新，Magpie 的代码变更与官方补充规则变更随 A 版本核对发布。
3. 按请求记录时间选择 Ultrafast 促销或常规价。目录更新后，让当前周期内原先缺价的本机记录重新得到可查估算，参考价格更新后本机相同条件的新统计采用新价。保留原始 Token、请求归属、使用时间和计价来源。会话汇总、设备卡片与预算占比复用同一计算结果。

### 3.3 档位识别、卡片与通知

A 端本机在原有日志解析上识别有据可查的 Standard、Fast、Ultrafast。按请求或会话事件关联模型与档位，有实际返回档位时采用实际档位，只有设置事件时明确标为「所选」。保留 `fast`、`priority` 的 Fast 兼容映射，并把 `ultrafast` 单独处理。已交付 B 仍按当前同步数据判断 Fast 与并发。若兼容数据明确给出同一次有效观察的 Ultrafast 状态，A 可据此显示品红色或红色。旧 B 未上报时显示未知或已有可确认状态。 [OpenAI API Fast 文档](https://developers.openai.com/api/docs/guides/fast-mode) · [OpenAI API Ultrafast 文档](https://developers.openai.com/api/docs/guides/ultrafast-mode)

在成功接收设备数据后统一判断每台设备的状态变化，再让卡片和 macOS 通知使用同一结果。按设备身份和最近一次已处理的用量、状态事件去重，保留跨重启的通知记录。普通使用的间隔按可确认的停用时段计算，长任务等待工具或观察断线均不能直接充当停用证据。原生通知交由 macOS 投递。卡片动效随可确认状态开始和结束。

### 3.5 A 端统一计价技术路线

1. 沿用 A 端 Go、Wails 和现有界面。A 在验证并读取 B 的同步记录后，以请求模型、时间、档位和 Token 生成仅用于展示的估算。原始同步记录仍作为用量和历史追溯的依据。现有 Magpie／Models.dev 和 Agent Speed 计价逻辑供本机与远端共用。 [设备记录读取](../../source/preview/codex-collector/internal/usagetracker/sync.go) · [A 端现有计价逻辑](../../source/preview/codex-collector/internal/usagetracker/pricing_sources.go)
2. 旧 B 只上传缓存 Token 合计，缺少缓存读写拆分时按缓存读取估算，并说明这个口径。按请求时间应用所选来源的日期规则，以原始输入及缓存合计判定长上下文档。保留旧 B 的「所选」或「未知」档位标记。所选档位能计价时按该来源的规则估算，缺少必要价格或档位时记为未计价。
3. 在 A 启动读取历史缓存、接收新同步以及选中价表有效更新时完成对应重算。切换来源后让逐条明细、卡片和汇总一次采用同一版价表。同步与换表重叠时，按当前已生效价表补算新记录。更新失败时沿用上一份有效价表和估算。
4. Wails 界面的价格设置和详情标注「A 端计价来源」。参考金额、模型汇总和预算占比读取统一结果。缺价提示纳入 A 端计价的真实设备请求，显示缺价范围或条数。同步、通知和活动判断继续使用原请求身份与用量。
