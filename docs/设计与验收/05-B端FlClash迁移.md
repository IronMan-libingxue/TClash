2. **CodeX Speed 页面。** 在左侧导航保留 CodeX Speed 入口，用 FlClash 的卡片、排版、间距、主题和交互重做页面。原有周期、缓存选项、项目／模型、Fast／并发、代理组流量和同步状态均纳入回归。仪表盘与页面读取同一份数据、周期和缓存选择。Mac 状态栏和 Windows 托盘就地展示原有简要信息。
3. **本机使用额度。** 两处显示「本机使用额度（参考）」，包含所选范围内已计价模型的参考美元总额和该金额占 A 设定周期预算的百分比。按同一批请求加总，应用现有 B 端设备显示倍率一次。部分缺价时标注未计价数量，全部缺价显示 `—`，零用量按无用量显示。跨周期的「全部已读记录」显示累计参考金额，预算占比只在有对应周期预算时显示。缓存开关沿用原口径，控制模型 Token 展示，缓存价格照常纳入估算。
4. **倍率提示。** 两处底部原样显示下列文案。同一说明标明适用模型与套餐内额度，参考金额按官方 API 档位费率估算。 [官方套餐内额度和积分规则](https://learn.chatgpt.com/docs/pricing#speed-multipliers) · [官方 API 定价](https://developers.openai.com/api/docs/pricing)

## 四、技术路线

### 数据接入和功能迁移

由 Flutter 桌面端管理现有 Go 采集器的启动、退出和恢复，沿用本机进程通信，扩展面向页面的用量合计及档位字段。复用原有日志解析、设备状态目录和授权、统计起点、上传进度、月流量及并发历史。将 FlClash 的内核连接统计接入现有代理组聚合，维持旧的计数口径。既有代理配置先在备用位置转换和校验，再切换生效。迁移按语义核对节点、策略组、规则、DNS、订阅、Merge、Script 和备份。采集继续读取 Codex 原有日志，Codex 配置和网络路径仍由用户原有设置控制。应用升级沿用 TClash 独立交付，价表通过现有私库自动更新。 [旧版采集器启动与通信](TClash-Preview/src-tauri/src/tclash_collector.rs)

### A 下发价表与统一估算

- A 保存生效来源或确认修正价格后，按现有私库发布签名版价表。已选来源的定时刷新通过校验后，可自动发布对应的有效更新。试算结果独立于生效设置。已确认的修正优先保留，后续目录刷新时仍按 A 已确认的价格发布。
- A 输出同一份可追溯的标准单价与档位规则，带版本、来源和适用时间。A 与新版 B 复用同一估算逻辑，先按请求时间和上下文选择输入、缓存、输出费率，再应用对应模型的官方 API 档位规则一次。GPT‑6.2 Sol／Astra、GPT‑6.1 Sol／Terra 和 GPT‑6 Astra 的 Fast 按 2 倍。GPT‑6.1 Sol 和 GPT‑6 Astra 的 Ultrafast 按 6 倍。GPT‑6.2 Sol 和 Astra 的 Ultrafast 在北京时间 2027 年 3 月 1 日 16:00 切换，由 3 倍变为 6 倍。只有日志所选档位时标为按所选估算，价格或档位无法确认时标注未计价。 [OpenAI API 价格表](https://developers.openai.com/api/docs/pricing) · [GPT‑6.1 Sol 计费](https://developers.openai.com/api/docs/models/gpt-6.1-sol#pricing) · [GPT‑6.1 Terra 计费](https://developers.openai.com/api/docs/models/gpt-6.1-terra#pricing)
- 价表与原预算策略分开发布。新 B 使用配对时已有的 A 公钥验签，并核对发布版本和内容，验证后整体切换并重算可见历史及新记录。A 切回某个来源时按新发布版本生效。B 保留原始用量，记录最近成功同步时间和实际用价版本。离线、损坏、签名失败或旧版本重放时沿用上次有效表。已配对但初次尚未收到价表时，参考金额显示待同步，原始用量照常展示。未配对仍可显示本机统计和原有本地参考价。价表异常时，既有用量上传和策略获取照常处理。旧 B 保持原协议并可继续同步。

### 一键升级和回退

向已装设备交付一个 TClash 原位升级包。更新桌面程序及其相关运行组件，沿用原安装身份、配对与授权、API 令牌、历史及代理设置。升级器定位已有安装位置，Windows 兼容非默认盘，Mac 沿用「应用程序」目录。先备份并验证新程序和迁移数据，再停旧程序与采集器、切换并启动。失败时恢复旧程序、配置及启动状态，保证单采集。同一设备后续的价表变化通过同步自动生效。新设备保留单个预授权安装包。 [既有一键交付要求](03-A端扩容与重新分发.md#七后续正式版的一键交付要求) · [Apple 应用签名与嵌套组件](https://developer.apple.com/library/archive/technotes/tn2206/_index.html)

先在隔离环境核对现有 A 和旧 B 的同步，再验证 A 发布价表时旧 B 可继续工作。新版 B 依次完成隔离迁移、Mac 与 Windows 实机试点和其余已配对设备分发。每一阶段保留可回退的程序和配置记录。

## 五、验收标准

| 验收项 | 可核对结果 |
| --- | --- |
| 界面与汇总 | Mac 和 Windows 的宽／窄窗口、浅／深主题下，卡片顺序符合图 1，旧模型信息完整。两个入口在同一时间范围内的合计和提示一致。以两模型参考金额 `$20` 和 `$30`、设备倍率 `1.5`、周期预算 `$900` 为例，B 两处均应显示 `$75.00` 和 `8.33%`。验证缓存开关、历史周期、零用量、部分缺价和全缺价。 |
| 价表下发和回退 | 验证 A 保存来源、修正价格和每日更新后，在线 B 在后续成功同步时使用同一版。用真实 Mac 4 和 Windows 2 历史请求核对明细、总览和预算，以及 Fast 费率、长上下文临界点、Ultrafast 生效时间前后。坏表、过期回放、离线及 A 切回来源均有可复现结果。两端在同价表、周期、原始记录和展示倍率下应等额。 |
| 活动与通知 | 覆盖单 Fast、单 Ultrafast、并发含 Ultrafast、结束和过期。旧 B 缺字段、自动子代理或仅有历史记录时，既有 Fast／并发统计和 A 的通知去重保持正确。 |
| 老设备兼容 | 未升级 B 与新版 B 可并存。在已配对的真实 Mac 和 Windows 各产生新请求，A 以原设备身份收到一次。核对升级前后 Token、请求数、统计起点、设备倍率和历史。断网、重启及重新联网后可同步。分发后逐台记录新版本和同步结果。 |
| 代理与迁移回退 | 用旧版实际配置的隔离副本核对节点、策略选择、规则、DNS、Merge、Script、系统代理、TUN、服务测试、导入导出和本地／WebDAV 恢复。核对系统服务、订阅链接处理和相关应用共存，以及 Mac 两行状态栏、Windows 托盘便签。验证 Windows 非默认安装路径、Mac 应用目录、重复运行升级包和中途失败回退。 |
