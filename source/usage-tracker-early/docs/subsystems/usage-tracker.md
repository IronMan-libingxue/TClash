# Codex 用量

Mac 1 运行 A 查看端。Mac 2、Mac 3、Mac 4、Windows 1、Windows 2 各运行一份 B 采集端。六台设备使用同一套用量口径，官方订阅额度按账号显示。

## 技术栈与设计指标

- Go 1.26.8 和 Wails 3。macOS 使用系统 WebKit，Windows 使用系统 WebView2。界面沿用 HTML、CSS 和 JavaScript。
- [采集](../../internal/usagetracker/collect.go)复用 Magpie 的 Codex 本机日志解析和定价。统计最多读取近 90 天记录，保留真实 Token、模型价格估算与官方额度读数。采集独立运行，Codex 继续通过官方订阅直连。
- [接入](../../internal/usagetracker/enroll.go)由 A 预授权设备。A 连接正式 GitHub 私库后，可为每台设备单独提供只限该仓库的 Contents 读写令牌并逐台生成安装包，也保留五台一批生成的后端能力。打开对应包里的安装程序后，B 生成本机身份和登记证明，A 自动验收并登记首次有效认领。Windows 包包含 x64 和 ARM64 程序，安装时自动选择。安装包含私库凭据，须按设备私下分发。A 已接受的授权凭据不能再次登记新身份。GitHub 上可单独撤销相应设备的令牌；令牌到期后需要更新设备授权。
- [同步](../../internal/usagetracker/sync.go)沿用 GitHub 私库和加密签名的用量包。A 保管解密钥匙。B 首次运行自动同步，此后默认每 5 分钟检查并上传变化。A 每分钟检查新用量，B 每分钟检查 A 签发的设置。A 调整全体 B 的上传间隔，B 在后台自动接收。用量无变化时复用上一份上传记录。
- B 登录后随系统运行，关闭窗口后由菜单栏或通知区域继续采集。A 可关闭，B 继续向私库写入，A 下次打开自动补读。断网或休眠后从本机日志继续补传。每 5 分钟为在线状态下的默认目标，首次回填、网络重试、系统休眠和 Codex 日志落盘时间会影响可见时刻。
- [总览](../../internal/usagetracker/view.go)默认用当前 Codex 七天重置周期，按一个口径同时呈现六台设备。每台卡片显示所有模型的实际 Token 合计、美元估算、折算占比、逐模型用量和数据时间。六台合计包含 A 本机且只计一次，官方额度独立显示。点击卡片进入设备、项目、模型、会话、请求和周期明细。用量更新通过文字和边框提示，查看明细后清除提醒。同步时间、缓存显示切换、金额系数调整和官方额度变化均不触发设备高亮。
- B 保留项目、模型、最近同步状态和含缓存显示开关。界面不显示设备总量、设置页和手动同步。展示值默认乘 1.5，周期估算总额默认 900 美元，A 可调默认系数、单机系数和周期估算总额。只有可归入账号周期且有价格的请求参与额度估算，未确认的官方读数显示缺失。
- A 的设备卡顶部显示所选重置周期内的 Token 合计和额度进度条。总览单列 A 本机折算已用金额和占比。设备总条和各模型条都以本周期估算总额为 100%，条宽与标注的折算占比一致，全部历史或缺少可折算记录时显示缺失。
- A 的设备卡按当前含缓存口径的 Token 用量排序，默认显示前三个模型。其余模型可以展开，设备合计始终包含所有模型。A 明细里的模型名称可点击，汇总所选设备、周期、项目、会话范围内各思考深度的 Token、请求数、美元估算和折算额度。思考深度取自 Codex 请求日志，旧记录缺少该项时归入「未记录」。
- A、B 各自在总览显示本机当前有日志记录的模型与速度，单位为 `tok/s`。本机每约 4 秒检查可用记录。优先以该请求输出 Token 除以首 Token 后耗时。缺少首 Token 时间时显示含等待的请求平均估算。没有足够记录时显示缺失。速度只保存在本机运行内存，从用量包和云端设置中排除。
- 本机验收使用唯一的 `Codex 用量.app` A 端。Mac 1 保持本机真实日志和账号额度来源，五台模拟 B 的加密测试记录从独立的本机测试目录读取。模拟卡片与模拟明细明确标注，顶部真实设备合计、账号额度和 Mac 1 用量仅由真实记录计算。A 可显示或隐藏模拟设备，尚未接入的真实设备显示等待状态。A 调整频率时，本机模拟设备也会自动接收；测试存储只接收间隔数值及其原有模拟设置，不复制真实账号规则或凭据。模拟数据不写入正式私库或真实设备配置。
- 官方额度是共享账号的读数，不代表每台设备或每个模型的官方消耗。设备和模型的美元与百分比依照日志、模型价格及所设周期总额估算；默认的 900 美元是可调整的估算基数，不是官方承诺的额度。不能归入账号周期的请求不进入该周期额度估算，并在界面提示数量。
- 正式私库只存接入证明、加密统计包和签名设置。现有 GitHub 测试私库只存模拟数据。用户已另行授权创建私有仓库 `IronMan-libingxue/codex-usage-real-sync-20261113`，用于真实设备加密统计；不将真实数据写进模拟测试仓库。

## 账号与额度口径

A 默认随当前身份切换，提供历史账号、全部账号日志总量与待确认视图；用户可逐条确认本机待确认请求。定时观察和日志交叉验证产生的账号归属必须标记为推定，无法判断的请求不计入单账号总计。详细规则与真实账号切换验收边界见[多账号设计](usage-tracker-accounts-proposal.md)。

官方百分比只能作为账号整体的读数，附读取时间；设备、项目、模型、请求的参考美元与用户自定义预算占比均非官方扣费或额度占比。$900 不是官方保证的额度。全部账号日志总量不能被误写为一个账号的用量。真实 B 尚沿用原采集逻辑，若 B 上也切换账号，其逐条账号归属尚需另外验证。

## 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 预授权和安装 | A 可按设备生成独立具名安装包；各设备令牌不同，Windows 安装包同时包含 x64、ARM64 程序。每个 B 首次运行自动登记和上传，A 同步后自动显示对应卡片。重复上传不新增设备。同一授权重新认领不会被 A 登记为新设备 |
| 总览与明细 | 六张卡同页，逐模型相加等于该设备 Token 合计；顶部合计只包含真实设备，各模拟设备不计入。切换缓存口径仍能对账。七天重置时按边界归属，官方额度只按账号显示一次。单台卡片可打开其逐条请求 |
| 提醒 | 只有新增或修正实际用量的设备高亮。没有新数据、仅调整频率或展示口径时不高亮 |
| 默认同步与调频 | B 首次联网同步，默认 5 分钟。A 改间隔后 B 在后台接收，无需在 B 操作。正常在线时，落盘用量约在一个 B 上传间隔加一个 A 检查间隔内显示 |
| 设备与模型进度条 | 总条覆盖设备全部模型，模型条与标注的折算百分比一致。默认显示 Token 用量前三，可展开其余模型。切换含缓存口径后顺序按当前 Token 重新计算，额度占比不受显示口径影响 |
| 思考深度 | 点击请求行里的模型可查看各思考深度。深度分组相加等于该模型在当前筛选下的 Token、请求数、美元估算和折算额度。旧记录的「未记录」纳入合计 |
| A 本机对账 | 从本机实际日志核对所选七天周期。A 本机总览、设备卡、模型和深度明细可逐层对账。折算金额、周期分母和账号官方读数分别显示 |
| 真实与模拟共存 | 同一个 A 端显示本机真实用量和五台带模拟标记的设备。开启、隐藏模拟后，真实设备的 Token、费用、折算额度及账号官方读数保持一致。模拟设备明细和思考深度可查看，明细来源明确显示模拟，模拟用量不计入真实总览。真实设备接入后，其同名模拟卡不覆盖真实卡 |
| 模型速度 | A 和 B 各自显示本机模型名、`tok/s` 和测量口径。切换模型后以本机日志记录为准，缺少该模型样本时显示缺失。上传数据中没有速度 |
| B 界面 | 显示项目、模型和最近同步状态。含缓存默认打开。看不到设备总量、同步设置或手动同步入口 |
| 读写边界 | 真实 Codex 日志只读。B 只上传加密统计。A 可以离线查看最近已收到的统计，网络恢复后增量补读 |

## 验收边界

本轮本机验收使用正式 A 的本机真实记录，同时从独立的本机测试目录读取五个模拟 B 的加密记录。此前还用隔离配置验证了登记、加密和同步。Windows 名称的模拟进程仍在 Mac 上运行。Windows x64、ARM64 和 Mac Intel 的产物构建属于构建验收。

设备验收另需在真实 Mac、Windows 上打开对应安装包，验证首次安装、关闭窗口后的后台采集、退出登录再登录、断网补传、不同网络的同步，以及实际环境下系统签名与 WebView2 的运行情况。正式用量需要指定正式私库。模拟测试和正式设备验收采用各自独立的配置与存储。

## 本机验收记录

2026-11-13 在一台 Mac 上运行 A 和五个模拟 B。A 一次生成五份模拟安装包，五个独立进程使用各自的授权文件启动，A 自动收齐六张设备卡。逐模型、逐设备和顶部合计在含缓存及不含缓存两种口径下均能对账，设备卡能打开对应请求明细。

通过 A 界面把间隔从 5 分钟改到 1 分钟后，B 自动收到了设置。Mac 3 增加 1,250,000 个模拟 Token 后，只有 Mac 3 卡片高亮，六台合计为 221,990,000 个 Token。试用配置恢复为 5 分钟。A、B 的本机速度各自显示，另用独立只读实例确认本机真实 Codex 日志能计算出速度。

本轮界面验收检查了六张设备卡的实际条宽、前三模型排序、展开其余模型和缓存开关。点击模型后核对了多种思考深度及「未记录」分组。另用 A 端真实日志核对当前七天周期的请求、输入、输出、缓存、美元估算和折算额度，设备、模型及思考深度逐层对账通过。

合并后的安装版 A 已在本机打开，确认 Mac 1 真实卡和五个模拟卡共处同一窗口。打开、隐藏模拟设备前后的真实汇总一致；模拟设备明细及思考深度显示模拟来源。模拟 Mac 3 产生新数据并重新启动采集后，A 自动读取并高亮该卡。再次对照本周期原始日志，核对了 4,930 条已稳定写入的请求，以及设备、模型和思考深度汇总。另有界面标示的请求无法归入该账号周期额度估算，不能据此声称它们的设备额度已知。模拟卡片的「数据」时间是用量最近变更的记录时间；没有变化的同步不会改写该记录。

在统一 A 窗口将模拟设备的同步间隔改为 1 分钟后，五台模拟 B 均自动接收；再改回 5 分钟后，五台均自动恢复默认间隔。模拟设置由测试端独立签名，测试期间没有接入正式私库。

对 310 条未归入当前账号额度估算的历史请求逐条核对后，用户确认了账号切换：其中 197 条属于切换后的 Pro 账号，113 条属于切换前的 Plus 账号。197 条按原请求、Token 和对应额度事件指纹建立逐条确认，重新读取时校验依据后计入 Pro 账号额度估算；113 条保持原归属。Token 和模型价格估算不因归属修正而改变。总览提示其他账号记录仍计入当前周期的 Token 总计及可计价美元估算，明细将它们标为「其他账号」；无法识别账号的记录另标为「待确认」。拟议的 A 端多账号自动切换和分账号总览见 [多账号提案](usage-tracker-accounts-proposal.md)，尚未实现。

实机安装、登录后台运行和异网同步仍需按验收边界测试。

## 构建

```sh
cmd/usage-tracker/build.sh release
go test ./internal/usagetracker
go test ./internal/davsync -run TestTrackerGitHub
```

`release` 在 Mac 上构建 A 端，并附带 Apple Silicon/Intel 通用 Mac 安装模板和 Windows x64/ARM64 安装模板。A 在「同步设置」中按设备生成 ZIP，解压后运行包内的 `Install.command`（Mac）或 `Install.cmd`（Windows）。用于交付主控端的完整 A ZIP 必须从包含 `Contents/Resources/installers` 的最终 A 应用打包，不可把缺少安装模板的 Mac B 模板误当成完整 A 包。桌面程序入口在 [cmd/usage-tracker](../../cmd/usage-tracker)，GitHub 用量传输在 [internal/davsync/tracker.go](../../internal/davsync/tracker.go)。
